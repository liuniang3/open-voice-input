# 会议实时转录

会议实时转录和短语音输入共用跨平台 Electron 客户端。Windows 使用 WASAPI，macOS 使用 AVAudioEngine 与 ScreenCaptureKit。macOS 系统音频采集最低要求 macOS 13；需要允许麦克风和屏幕/系统音频录制，自动粘贴另需辅助功能权限。

## 使用流程

1. 在模型设置中配置普通 MiMo API 的 `mimo-v2.5-asr`，也可以选择已保存的 Qwen3-ASR-Flash 非实时模型配置。MiMo Token Plan 不用于专用 ASR。
2. 打开“会议实时转录”，选择麦克风与系统音频，或仅麦克风。可提前选择 Markdown 文件路径。
3. 点击开始，或按设置中的会议快捷键。再次按快捷键只置前当前会话。
4. 每约 30 秒提交一个录音片段，文字在模型返回后显示。Markdown 每 30 秒自动保存，停止时再保存一次。它是分段实时预览，不是逐字 WebSocket 输出。
5. 停止后等待剩余转写结束。可选择一个已配置的清理模型执行“语言清理”，结果写入单独的 `.cleaned.md` 文件。录音期间不会执行清理，也不做说话人分离。

## 文件保留

- 未指定位置时，在系统“文稿/Documents”下的 `Open Voice Input/Meetings/` 新建唯一 Markdown 文件。
- 如果所选 Markdown 已存在，会在文件中追加本次会议的独立标记区块，热保存只更新该区块，保留区块外原笔记及后续编辑。界面显示实际输出路径。
- 如果录制时用外部编辑器修改本次会议的标记区块，自动保存会提示冲突；最新原文仍保存在本机会话记录中，外部修改不被覆盖。停止后点“重试未完成片段”会在默认目录新建恢复稿；最终保存成功前退出会被阻止。避免让多个程序同时重写同一会议区块，文件系统不提供跨编辑器的事务锁。
- 会话目录在 Electron 的 `userData/meeting-sessions/<会话编号>/` 下。Windows 默认 `%APPDATA%/open-voice-input`，macOS 默认 `~/Library/Application Support/open-voice-input`。
- `audio/microphone/`、`audio/system/` 保留原生采样格式的持久化录音片段和索引。
- `realtime/microphone-complete.wav`、`realtime/system-complete.wav` 是持续写入的完整 16 kHz 单声道音频，分别保留两个来源。没有按 API 上限截断；超过 RIFF 上限时使用 RF64 头。
- 转写将两个来源按时间窗口混合，不生成讲话人标签。使用耳机可减少扬声器声音再次被麦克风录入造成的重复；目前没有回声消除。

## 失败与恢复

录音先落盘，网络请求串行从本地完整音频读取小片段。请求失败最多自动尝试三次，退避重试不会暂停录音。失败片段在 Markdown 中保留占位，停止后可以重试，已成功的片段不会再次请求。

重启会读取历史会话及持久化状态，修复音频头和未登记的已落盘尾段。不会自动启动录音或发送 API 请求，用户可选择会话后重试。恢复依赖已经写入磁盘的内容，突然断电时尚未提交的操作系统/设备缓冲不能保证恢复。

语言清理按有限长度拆分纯文本，逐段缓存结果；验证返回结果保持原文字符顺序及最低保留比例，不接受扩写或解释。分段清理缺少跨段语境，模型质量仍可能影响清理效果；原文和原始音频始终保留供复核。

## 验证边界

自动化覆盖音频尾段、双轨存档、断网重试、并发开始、外部编辑保护、崩溃检查点重放、静音来源、慢请求时保存及权限失败。macOS 原生捕获需要在 Mac 上编译并授权后验证，Windows 测试不代替 Mac 真机验收。多小时真实会议、设备拔插、睡眠唤醒和平台安全权限变化仍需实际使用验证。
