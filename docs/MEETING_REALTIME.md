# 会议实时转录

会议实时转录使用独立于短语音输入的会话、原生录音和持久化状态。Windows 使用 WASAPI，macOS 使用 AVAudioEngine 与 ScreenCaptureKit（macOS 13+）。录制时可选择阿里流式识别，或在阿里服务不可用时改用 `mimo-v2.5-asr` 非实时分段转录；停止后显式生成详细内容整理与思维导图，可选 MiMo 全音频复核作为额外证据。

本文描述当前开发版。阿里模型提供实时草稿，MiMo 备用模型按用户选择的转录间隔提交已落盘音频，不伪装成实时流。转录间隔与 Markdown 自动保存间隔分别设置、互不等待，默认均为 30 秒。

## 模型和凭证

| 环节 | 当前模型 / 接口 | 何时调用 |
| --- | --- | --- |
| 会议转录 | 默认 `qwen-audio-3.0-asr-flash-streaming`，可选 `fun-asr-realtime`；备用 `mimo-v2.5-asr` 非实时分段模式 | 阿里模型持续流式发送；MiMo 按所选间隔提交独立片段；停止后均可重试缺口 |
| 音频复核 | 可选 `mimo-v2.5-asr`，普通 MiMo 或 Token Plan ASR API | 停止并完成音频收尾后，勾选复核并生成摘要 |
| 总结 / 思维导图 | 单独配置的语言供应商与模型，支持 Chat Completions / Responses | 用户明确点击“生成摘要”；与实时 ASR 凭证隔离 |

两个阿里实时模型使用 `/api-ws/v1/inference` 的 `run-task` / `finish-task` 协议，默认地址为 `wss://dashscope.aliyuncs.com/api-ws/v1/inference`。应配置与模型、地域及账号相匹配的地址和 Key。常见 HTTPS REST 基址会转换为同主机的 WebSocket 路径；不会因为切换模型而替换成另一个模型的凭证。

`qwen3-asr-flash-realtime` 使用不同的 `/realtime` 协议，不能当作新 Streaming 模型使用；普通 `fun-asr` 文件接口也不是 `fun-asr-realtime`。当前会议流式传输只接受上述两个准确的阿里模型 ID。`mimo-v2.5-asr` 走 MiMo 文件式 ASR API，不建立 WebSocket，也不会显示尚未定稿的实时草稿。

MiMo 会议转录和会后复核都使用共享的 MiMo 连接，支持普通 API 地址与 Key，也支持 Token Plan 的 `https://token-plan-cn.xiaomimimo.com/v1` 与 `tp-` Key。阿里实时识别、MiMo ASR 和 LLM 各按所选模型解析配置，不跨供应商借用 URL 或 Key。选择阿里转录且不开启复核时不会要求 MiMo 凭证。

## 音源和权限

| 模式 | Windows | macOS |
| --- | --- | --- |
| 仅麦克风 | WASAPI capture 端点 | AVAudioEngine，需要麦克风权限 |
| 仅系统声音 | WASAPI render 端点 loopback | ScreenCaptureKit，需要屏幕/系统音频录制权限 |
| 麦克风 + 系统声音 | 两条独立 WASAPI 音轨 | AVAudioEngine + ScreenCaptureKit，需要对应两类权限 |

**仅系统声音不打开麦克风、不请求麦克风权限。** macOS 的此模式也不创建 AVAudioEngine。Windows 在激活音频客户端前校验所选端点方向；错误设备或不支持的新模式会报错，不能回落到麦克风。

macOS 系统音源是显示器过滤的系统混音，不是 Windows 的硬件输出端点。ScreenCaptureKit 的视频回调立即丢弃，不保存屏幕画面。自动粘贴另需辅助功能权限，与会议录音分开。屏幕权限变更可能要求重新启动，最终签名应用的权限归属仍需 Mac 实机检查。

## 使用流程

1. 在会议模型设置中配置所选模型：阿里 Streaming / Fun-ASR 使用阿里连接，`mimo-v2.5-asr` 使用普通 MiMo 或 Token Plan 连接。会后需要摘要时，另行配置语言供应商与模型。
2. 打开“会议实时转录”，选择仅系统声音、仅麦克风或双轨，可提前选择 Markdown 文件路径，并分别选择转录间隔和自动保存间隔。
3. 点击开始，或按设置中的会议快捷键。再次按快捷键只置前当前会话。
4. 录音始终先写入本地。阿里模式再以有界 PCM 数据包发送到 WebSocket，实时草稿可以被后续草稿替换，只有确认句子进入已确认原文。MiMo 模式按转录间隔封存并提交独立片段，界面明确显示“非实时分段转录”。
5. 开始成功后自动进入悬浮窗。可置顶、调整字体、暂停/继续或停止并保存，也可返回详情；详细页面的悬浮窗按钮在转写阅读区正上方。窗口切换不新建录音、不触发模型处理。
6. Markdown 按所选自动保存间隔独立保存，默认 30 秒，暂停和停止时也会保存。网络请求不会阻塞原生音频落盘，自动保存不以 ASR 返回为前提；调整保存间隔不会改变转录分段。
7. 停止后等待原生尾段封存、WAV 收尾以及流式或分段任务结束确认。超时或连接失败会保留缺口供重试，不能当作全部转写完成。停止本身不触发会后复核或 LLM。
8. 按需生成摘要，并决定是否开启 MiMo 音频复核。录制或暂停状态都不能运行会后处理；实时流程不做讲话人分离。
9. 页面顶部的“历史记录”用于搜索和加载以前的实时会话。加载历史只读取本地状态、Markdown 和完整 WAV，不自动启动录音或发送 ASR 请求；加载后可显式重新生成摘要、选择 MiMo 复核或重试转录缺口。录制期间不能切换历史会话。

## 暂停和悬浮窗

暂停前封存当前未满分块的音频；原生日志写入 `pause_begin` / `pause_end`。继续录制沿用原来的文件序号与音轨，不重新覆盖音频。Windows 暂停/继续结果会有界等待各写入线程确认；macOS 通过串行归档队列完成封存和日志操作。

暂停期间的源音频帧被丢弃，不作为录音内容保存；暂停不等于释放音频设备或撤销权限。系统-only 始终没有麦克风采集。WAV 保留已采集音频及时间轴空洞，不能把暂停区间理解为实际录到的声音。实时连接在暂停时收尾，继续后从后续归档位置发送，显示时长在暂停时冻结。

悬浮窗、自动小窗口与置顶都是会议窗口状态，不再提供独立的“精简”档位。录音状态以后台确认结果为准，恢复详情不会重启会话；退出应用仍需完成停止和最终保存。

## 可选音频复核

当前界面不再提供单独的“校订”操作。“生成摘要”使用独立选择的语言模型；“MiMo 音频复核”决定是否先重新识别完整保存音频并比较两份来源。

- **开启复核：** 按时间顺序覆盖完整录音，包含已保存的静音区间。当前 MiMo 适配器每个请求最多 30 秒、2 MiB，在上限附近尽量找安静边界。每段音频和结果均有检查点，完成的段落校验后可复用。复核处理的是全部音频，不只取开头、尾部或已有转写缺口。
- **不开启复核：** LLM 只依据原始转录整理内容，不调用 MiMo ASR，也无法凭文本恢复没有识别出的音频内容。
- **开启复核后的内部比较：** 结合实时原文与 MiMo 证据，修正有依据的识别错误后再总结；保留有意义的重复、数字、否定和条件。存在分歧或边界不确定时标记待确认，并保留来源版本供核对。历史独立校订产物仍保留，不因新界面删除。

源引用、格式和内容保留检查可以阻止一部分错误输出，但不能证明模型语义判断正确。原始转写、MiMo 复核稿和校订稿分别保留，人工复核仍应对照音频。更改模型、来源或处理选项可能产生新的任务与结果；不要把旧检查点视为不同模型的可互换结果。

## 总结和思维导图

“生成摘要”是独立操作，不会因录音停止而自动运行。默认处理不可变的原始转录，开启复核时增加 MiMo 识别证据；不会自动拿旧校订结果代替新输入。执行前可以重新选择语言供应商与模型，它与实时 ASR、可选复核 ASR 的凭证独立。文件转写也使用同一摘要引擎。

新摘要的左侧继续显示可追溯的层级思维导图，右侧改为说话内容本身的连贯正文，不再按概览、决策、行动项拆成纪要条目，也不把逐条来源插入段落之间。模型可以理解语境、整理语序和去掉无语义口头词，但不得虚构事实、遗漏重要限定或回答录音中的问题。证据仍保存在结果 JSON 与左侧脉络中；旧版本纪要按原格式读取。新的摘要生成使用独立缓存标识，不会直接复用之前完成的旧格式纪要。

结果包括逻辑清晰的连贯段落、讨论详情、决策、行动事项、分歧和待确认问题，以及带层级的思维导图。条目和导图节点附带来源证据，不应编造负责人、期限或结论。界面显示层级结构；Markdown 导出包含嵌套列表形式的导图和详细纪要，不承诺独立图片文件。

### 流式等待和重试

摘要以 `stream: true` 调用所选供应商，分别处理 Chat Completions SSE 和 Responses 事件。界面只显示连接、思考、接收字符计数、等待、重试和校验状态，不提前展示未完成 JSON 或模型思考原文。

持续生成不再受固定总时长限制。模型设置中的超时用于建立连接及等待提醒；接收阶段使用网络空闲检测，默认至少 5 分钟无任何数据才中断。心跳可以维持连接，但不能伪装成新内容；长时间没有模型进展会显示继续等待，可手动取消。服务端、代理或网络仍可能有自己的时间限制，本地无法取消这些外部限制。

连接失败、网络中断、未完成 EOF、限流和明确的临时服务器错误最多自动重试 5 次，即初次请求加最多 5 次重发。采用 2 秒起的指数退避与随机抖动，默认退避上限 30 秒，并优先遵循供应商的重试时间提示。认证失败、上下文拒绝、输出达到上限、无效格式等不能靠重复请求修复的错误直接报告。

兼容 API 的重试会重新生成当前任务，不是恢复远程任务。不同尝试的半截内容不会拼接；可能发生额外计费。已通过校验并落盘的任务可以复用，只有失败项需要重新请求。实时会议的“取消生成”会中断接收与退避等待；取消不改变原文或音频，之后可重新生成。文件摘要沿用文件工作区的取消机制。

### 后台生成与切换页面

会议和文件转写的摘要任务由主进程持有。开始生成后，可以切换到主页、设置或其他工作区，也可以最小化窗口；切换页面只暂停该页面的轮询与绘制，不取消模型请求。后台状态订阅继续接收进度和完成结果，返回原工作区会恢复最新进度及已保存结果，不会自动重复调用模型。完成时不抢焦点、不强制打开原页面。

文件任务按会话隔离，切换到另一文件不会将之前文件的进度或结果写到当前文件。晚到的启动响应、状态读取及旧任务通知不能覆盖较新的结果。只有明确点击“取消生成”才取消对应任务。此处“后台”指应用仍在运行，包括托盘驻留；完全退出应用或关闭电脑不保证请求继续，未完成任务可依照已有检查点显式重试。

### 模型预算与分段

预算读取所选供应商模型的上下文、最大输出与超时配置，不从名称借用其他供应商凭证。优先一次处理整份文本；只有完整请求超过预算，才进行分层摘要与合并。估算包括系统指令、JSON 元数据、证据编号及文本，并预留约 20% 上下文余量和输出空间。估算不是供应商精确 tokenizer，实际网关上限不符时会明确提示上下文拒绝。

当前摘要输出预留最多 32768 tokens，且不超过所选模型输出限制和上下文的四分之一。输入还受输出预算六倍的约束，避免超大输入需要的详细段落与来源引用塞不进输出。上下文很大但输出很小的模型仍可能需要分层，这不是按旧固定 24000 字符机械切段。未知模型默认 128k 上下文、8192 输出；可在模型能力设置中调整为实际支持值，不能假设任意自定义网关都支持 250k。

只改变传输超时或单轮请求数量不会使同计划已完成任务失效；兼容旧缓存的首次采用会保留持久映射。模型、思考级别、源内容或预算/分段计划变化可能产生新的任务，因此旧版本的每一份缓存并不保证可直接复用。

## 文件保留

- 未指定位置时，在系统“文稿/Documents”下的 `Open Voice Input/Meetings/` 新建唯一 Markdown 文件。
- 如果所选 Markdown 已存在，会在文件中追加本次会议的独立标记区块，热保存只更新该区块，保留区块外原笔记及后续编辑。界面显示实际输出路径。
- 如果录制时用外部编辑器修改本次会议的标记区块，自动保存会提示冲突；最新原文仍保存在本机会话记录中，外部修改不被覆盖。停止后点“重试未完成片段”会在默认目录新建恢复稿；最终保存成功前退出会被阻止。避免让多个程序同时重写同一会议区块，文件系统不提供跨编辑器的事务锁。
- 会话目录在 Electron 的 `userData/meeting-sessions/<会话编号>/` 下。Windows 默认 `%APPDATA%/open-voice-input`，macOS 默认 `~/Library/Application Support/open-voice-input`。
- 启用音轨的 `audio/microphone/`、`audio/system/` 保留原生采样格式 PCM、索引和日志。创建会话可能预建空目录；仅系统模式不会写入麦克风录音。已有录音目录禁止作为新的原生写入器目标。
- 启用音轨分别写入 `realtime/microphone-complete.wav`、`realtime/system-complete.wav`，保留完整 16 kHz 单声道音频。没有按 API 上限截断；超过 RIFF 上限时使用 RF64 头。原生 PCM 保持不变，WAV 是派生完整音频。
- 转写将两个来源按时间窗口混合，不生成讲话人标签。使用耳机可减少扬声器声音再次被麦克风录入造成的重复；目前没有回声消除。
- `realtime/state.json` 保存音频读取位置、流式窗口、确认文本和失败状态。实时草稿如写入 Markdown，会单独标注“尚未确认的实时文字”，不能混作确认原文。
- 原始 `.md` 之外，可选复核写入 `.reviewed.md`，校订写入 `.cleaned.md`，详细总结与导图写入 `.summary.md`。派生文件已存在时另选文件名，界面显示实际路径，保留以前的输出和用户编辑。
- `realtime/postprocess/<内容指纹>/` 保存复核、校订、总结的任务检查点和结构化结果。分段、缓存、网络重试都不删除或缩短本地音频。

## 阅读区域与悬浮窗

详细会议页面的转写区、摘要区和文件转写结果区下方都有拖动条，可以独立调整阅读高度，不需要通过撑大整个窗口才能查看更多内容。拖动条支持上下方向键调整，双击或按 Home 恢复自动布局；阅读高度保存在本机。悬浮窗中的原文与实时文字之间也有分隔条，可调整两部分的占比。

悬浮窗不再提供手动“精简”档。首次默认尺寸为 640 × 560，之后记忆上一次正常尺寸和位置；返回详细页面时恢复详细窗口原有的位置、尺寸及最大化状态。更换显示器后会将记忆位置约束到可见屏幕内。

悬浮窗顶部仅显示文件标题及置顶、返回详情图标，录制控制区提供暂停、停止并保存、字体滑块和计时。状态用指示灯表示，绿灯表示正常/已完成，黄灯表示启动、暂停、重连或收尾，红灯表示错误或连接故障；悬停可查看文字说明。队列数量、自动保存说明、“原始转写”和“实时草稿”标题在悬浮窗中隐藏。未确认文字仍通过浅色背景区别，未被写入已确认原文。

当窗口宽度小于 420 或高度小于 260 时自动进入仅实时文字视图。鼠标移出时隐藏恢复按钮、字体及透明度滑块，即使滑块仍有键盘焦点也不会保持显示；鼠标移入时恢复默认 90% 不透明背景并显示控件。字体范围为 12–28 px，背景不透明度范围为 0%–100%，该透明度用于鼠标移出时；悬停不会覆盖已保存的透明度。恢复按钮回到此前记忆的正常尺寸。为避免连续拖动缩小时把临界尺寸误当成正常尺寸，进入小窗口时不覆盖此前稳定的正常尺寸。最小窗口为 240 × 100。

Windows 的“小窗口 + 0% 背景”使用隔离的透明预览窗口，普通窗口继续使用原生缩放边框和毛玻璃。透明预览仅接收当前文字与显示偏好，不接收供应商配置或录音权限；提供边缘缩放及恢复按钮，移入空白透明区域时也能恢复背景。macOS 继续使用已有的原生透明窗口；这些显示变化不重启采集或转写。

尺寸、位置、字体与背景不透明度单独保存在用户数据目录的 `meeting-window.json`，不包含密钥、音频或转写内容。这些显示偏好不影响原生录制、上传分段或 Markdown 保存。

## 失败与恢复

转录从持续写入的完整归档读取有界音频。阿里模式轮换流式连接窗口，MiMo 模式按所选转录间隔建立独立分段任务；两者都不限制会议总长度，也不会为满足供应商限制而截断本地音频。断线或请求失败后，未完成窗口、未发送区间、分段任务及已确认句子保留检查点。失败项不会因为后续请求成功而消失，停止后可以明确重试；不能仅按文本相同就删除真实重复发言。

客户端的阿里连接窗口仍以最多 10 分钟为界，但旧窗口发送完成后会在后台等待最终确认，新窗口立即连接并继续发送后续归档音频。正常轮换最多同时存在一个收尾连接和一个实时连接，不重复上传相同音频。这消除了原先在 10、20 分钟等边界等待旧连接最终回执才开始新连接的串行停顿；新连接本身仍需要握手，网络或供应商故障仍可能造成延迟。旧窗口最终确认失败会留下可重试缺口，不会终止后续实时预览；停止、暂停和退出仍等待或安全终止所有收尾连接。

重启会读取历史会话及持久化状态，修复音频头和未登记的已落盘尾段。不会自动启动录音或发送 API 请求，用户可选择会话后重试。恢复依赖已经写入磁盘的内容，突然断电时尚未提交的操作系统/设备缓冲不能保证恢复。

MiMo 复核、LLM 校订和总结分别保留有界任务及检查点。超时、截断返回、无效 JSON 或缺乏有效证据会留下可重试状态，不能发布为完整成功。恢复时对音频和任务输入进行校验，复用匹配的已完成结果；失败任务由显式操作继续，不自动重跑整场会议。

原生采集、转写网络请求和可配置的 Markdown 自动保存计时器相互独立。ASR 网络故障不应停止录音；磁盘写入失败或设备故障仍可能使原生采集停止，此时应保留已提交音频并恢复，不能继续宣称录制正常。

## 开发接口和验证

先调用 `createAndPrepareSession()` 取得 `sessionId`，再调用共享采集服务：

```js
await service.start({ sessionId, captureMode: "system", systemDeviceId });
await service.pause(sessionId);
await service.resume(sessionId);
await service.stop(sessionId);
```

`captureMode` 支持 `microphone`、`dual`、`system`，默认 `dual`。兼容接口 `startMicrophone()`、`startDual()` 保留，并新增 `startSystem()`。系统单轨要求 helper hello 声明 `system_only`；旧 helper 会报 `helper_capability_missing`，应重新构建，不能用双轨静音麦克风来替代。

```text
npm run build:helper
npm run check:helper
node scripts/test-meeting-system-capture.js
node scripts/test-meeting-native-system.js
node scripts/test-ali-meeting-stream.js
node scripts/test-meeting-preview.js
node scripts/test-meeting-postprocess.js
node scripts/test-summary-streaming.js
node scripts/test-summary-budget.js
npm run test:all
```

Windows 原生单元测试需在 MSVC 开发环境执行 `cargo +1.85.1 test --locked --manifest-path native/audio-capture-helper/Cargo.toml`。`test:all` 自动发现新增测试。平台 CI 包含 Windows x64、macOS Intel 和 Apple Silicon 构建；提供 CI 配置不等于本次未提交改动已经在这些 runner 上通过。

自动化覆盖三种音源的共享接口、旧 helper 拦截、暂停/恢复、原生合成 PCM 封存、流式协议和重试、完整音频复核、独立校订/总结、凭证隔离及窗口控制。协议和模型测试使用模拟响应；不代表真实供应商账号、地域或服务质量已验证。
