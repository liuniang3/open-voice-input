# Open Voice Input v0.4.23

本次更新重点改善会议和文件摘要的请求可靠性，减少完整结果被误判为失败、字段格式错误和不必要的重新生成。

## 摘要生成与恢复

- 修复流式正文已经完成，却因尾部半条用量统计消息而报错的问题。真正的中途断流、损坏和输出截断仍会明确处理。
- 取消不准确的“最大输出 token × 2”字符限制，将模型容量、当前任务预算与本地响应安全界限分开。短任务不会直接请求模型的全部输出容量，长任务按内容和配置增加预算；没有统一设置 2048 token 上限。
- 简化模型返回结构：生成连贯正文、章节子主题和来源 ID；由本地建立编号、原文引用和思维导图章节链接。安全的缺省字段、空叶节点和已知元数据不再导致整段结果被丢弃。
- 对无效来源 ID 等真正的结构问题，提供具体字段反馈并进行一次有界重新生成；保留原文及已经完成的阶段。
- 区分真实上下文超限、输出上限和不支持的 JSON 模式。容量失败仅拆分当前失败批次，保存拆分计划，重试时复用成功的子任务。

## 供应商与模型

- 流式 Chat Completions / Responses 使用 OpenAI JavaScript SDK，继续支持自定义供应商 URL、独立 Key、兼容请求头及后台处理。
- 网络取消、持续无数据等待及最多五次网络重试由应用统一管理；SDK 不额外叠加重试。网络重试重新发起当前请求，不是接续已返回的 token。
- 未配置思考强度时，日常 DeepSeek/MiMo 摘要默认关闭思考，GPT 使用低强度思考；用户设置的强度优先。
- 增加 MiMo V2.6 Flash、GPT 6.1 Sol 的兼容能力预设，保留供应商和用户手动覆盖。渠道明确拒绝 JSON 模式或给出更低输出上限时，在同一模型/供应商内进行一次对应的兼容调整。
- 修复 SDK 请求头大小写重复造成严格网关拒绝的问题，并阻止继承其他账户的环境密钥、组织或项目设置。

## 验证与现状

- 73 个共享回归脚本、18 组稳定性测试通过，覆盖两种协议、用量尾帧、真实截断、请求头、凭证隔离、取消和拆分恢复。
- 用合成文本完成三种模型、九种场景的真实 API 回归。密集文本中，三者均保留 24 组项目编号、缓存值与响应目标；原始输入未改变。
- 当前 MiMo 渠道的响应等待仍有明显波动，不能保证固定速度；高重复长文和自动数值检查不等于所有复杂会议内容的完整质量验收。
- Windows x64、Intel Mac x64 和 Apple Silicon Mac arm64 共用这次改进。macOS 原生采集、权限和粘贴的真机验收仍单独进行。

## 下载与升级

- Windows：`Open-Voice-Input-Setup-0.4.23-x64.exe` 安装版，或 `Open-Voice-Input-Portable-0.4.23-x64.exe` 便携版。
- Apple Silicon Mac：选择文件名含 `arm64` 的 DMG 或 ZIP；Intel Mac：选择含 `x64` 的 DMG 或 ZIP。macOS 包目前未签名、未公证。
- 提供 Windows/macOS 更新元数据、blockmap 和 SHA-256 校验文件。已有用户可在应用的“关于与更新”中检查更新；未签名 Mac 的更新仍需要替换下载后的应用。
- 升级保留本机供应商配置。发布包不包含 API Key、个人配置、真实录音或转写、诊断截图及供应商响应正文。
