# Open Voice Input v0.4.21

本次更新让语音输入法在快捷键呼出时优先显示在光标或输入框附近，并修复 Codex 聊天输入框中定位失效的问题。

## 输入框跟随

- Windows 优先使用原生光标或 UI Automation 输入框位置，处理多显示器和不同缩放比例；macOS 使用辅助功能提供的位置。
- 优先放在输入位置下方，空间不足时放在上方，并限制在显示器可用区域内。
- 兼容尚未就绪的 Chromium 辅助功能树与深层富文本编辑器。Codex 输入框所属窗口位于第 31 层，原先的 24 层查询会提前失败；现在允许最多 64 层，并保持整个原生查询 700 毫秒的超时保护。
- 无法可靠定位时回退到显示器中央；保留原来的粘贴目标。录音期间手动移动的窗口不会被持续拉回。
- 只读取位置、大小与必要的窗口归属信息，不读取输入框文字。新增定位日志仅记录定位方式与耗时，不包含窗口标识或输入内容。

## 验证与下载

- 本地共享回归 `69/69` 通过。原生 Windows/Electron 测试覆盖普通输入框、深层空白/非空富文本编辑器、实际录音流程中的最终弹窗位置、粘贴目标保留及取消录音。
- 已验证能从本机 Codex 聊天输入框读取有效位置。Codex 中以输入框边界定位，不保证取得精确文字光标坐标。
- Windows x64、macOS Intel x64 与 Apple Silicon arm64 平台 CI 已通过；发布流程再次运行共享测试、原生组件构建与敏感信息检查。
- Windows 提供安装版和便携版 EXE；macOS 提供各自架构的 DMG、ZIP，附自动更新元数据、blockmap 与 SHA-256 校验文件。
- 安装包不包含用户 API Key、本地设置、音频、转写记录或诊断截图；升级沿用现有用户配置。
- macOS 包仍未签名。构建通过不等于已经完成 Mac 真机定位、录音、权限和粘贴验证；没有辅助功能权限时不会为定位额外弹出授权请求，而是使用回退位置。部分应用不提供可靠输入位置时也会回退。

## English Summary

- Dictation opens near the caret or focused input field, using Windows native/UI Automation geometry or macOS Accessibility geometry. Mixed-DPI conversion, display clamping and a centered fallback keep the popup visible.
- Fix cold Chromium accessibility queries and deeply nested rich editors, including the Codex chat composer. Ancestor traversal is bounded at 64 levels and the entire native query retains its 700 ms deadline.
- Preserve the original paste target and manual popup moves during recording. Read geometry only; placement logs contain the method and timing, never input text or target identifiers.
- All 69 local shared regression scripts and Windows/macOS platform CI passed. Real Codex input geometry was checked on Windows; macOS hardware behavior remains unverified.
- Windows installer/portable and unsigned macOS Intel/Apple Silicon downloads include update metadata and checksums. User credentials and local recordings are excluded.
