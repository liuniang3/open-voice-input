# Open Voice Input v0.4.20

本次更新改善长音频转写的分段与失败恢复：优先在停顿处切段，识别输出截断时自动拆成更短请求，复用已成功的结果，持续保留完整录音。

## 文件转写

- 千问与 MiMo 专用 ASR 不再携带任意的 2048-token 输出上限及语言模型采样参数；正常的表达整理与摘要输出预算保持原有设置。
- 只有正常结束的 ASR 响应才能发布为成功结果；输出被截断或响应提前中断时保留可恢复状态。
- 优先在约 180 秒附近的停顿处分段，遵守各供应商独立的时长、编码大小预算。千问文档的五分钟上限与客户端 210 秒 / 9 MB Base64 安全预算分开处理。
- 截断或旧任务音频过大时，仅拆分受影响范围。先保存子任务计划再请求，取消、失败或重启后复用成功检查点，按原音频顺序拼接。
- 处理中即可阅读和导出已成功部分；明确标注缺失区间及不完整导出。尚未完成或已经失效的原文不会作为完整摘要来源。

## 实时会议

- 阿里流式连接在已发送音频达到 9 分 30 秒后，优先在持续约 300 毫秒的安静区间轮换；持续讲话时最迟仍在 10 分钟切换。
- 已读入但未发送的音频交给下一连接，保持连续覆盖，避免遗漏和重复上传。旧连接等待最终确认时，新连接继续预览；失败窗口保留原来的范围供重试。
- MiMo 备用转录在所选 1–30 秒间隔末端附近寻找约 200 毫秒的停顿，不为寻找停顿延长等待。停止时保留未满间隔的尾段。
- MiMo 明确返回输出截断时，自动拆分为连续子段并先保存恢复计划。最多拆分 5 层，子段至少 1 秒；无法继续恢复时保留缺口，避免无限请求。不完整的返回文本不会混入成功原文。
- 子任务使用独立 ID，最终仍按音频时间排序。迟到的麦克风或系统音频会使对应旧响应失效；成功缓存与退出恢复不会漏掉未完成子段。
- 完整原生录音、全长 WAV、转写网络请求及 Markdown 自动保存继续独立运行。停顿检测只选择上传边界，不删除安静音频、不按相同文字删除真实重复发言。

## 验证与下载

- 本地完整共享回归 `68/68` 通过，包含会议预览 `32` 项、会议服务 `28` 项测试。测试使用合成音频与模拟响应，覆盖逐帧音频完整性、轮换、截断、失败、取消、重启与成功缓存复用。
- Windows x64、macOS Intel x64 与 Apple Silicon arm64 平台 CI 已通过。发布构建再次运行共享测试、原生 helper 构建与敏感信息检查。
- Windows 提供安装版和便携版 EXE；macOS 提供各自架构的 DMG、ZIP。附自动更新元数据、blockmap 和 SHA-256 校验文件。
- 安装包不包含用户 API Key、本地设置、音频、转写记录或诊断截图。
- macOS 包仍未签名；构建通过不等于原生录音、权限和粘贴已完成实机验证。背景噪声或连续讲话时仍可能使用硬切点，停顿检测不保证每个边界都落在完整句子之间。

## English Summary

- Dedicated Qwen/MiMo ASR omits arbitrary language-model output caps and sampling parameters, and rejects truncated or unfinished responses before publishing text.
- File transcription prefers pauses, enforces provider-specific upload budgets, persists adaptive split plans and exposes completed ranges with explicit partial-export and summary-source checks.
- Alibaba live connections prefer quiet boundaries from 9m30s and keep a ten-minute hard limit, passing unsent read-ahead to the next task without gaps or duplicate PCM.
- MiMo live fallback prefers pauses within the configured interval and recovers explicit output truncation through bounded, checkpointed child requests. Successful ranges survive cancellation/restart and remain chronologically ordered.
- Full native audio and WAV archives remain intact; ASR and Markdown autosave stay independent. Windows and unsigned macOS Intel/Apple Silicon distributions include update metadata and checksums.
